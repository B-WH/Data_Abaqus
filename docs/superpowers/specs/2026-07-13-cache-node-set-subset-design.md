# 缓存节点集直接提取设计

## 目标

在“已有缓存”模式下，允许用户不提供目标点文件，直接按缓存中保存的节点集筛选原始节点数据，并另存为一对新的 NPZ/metadata 文件。整个过程不打开 ODB，不执行插值，也不修改源缓存。

## 界面行为

- 提供目标点文件时，继续使用现有目标点插值流程。
- 未提供目标点文件但选择了至少一个节点集时，执行节点集直接提取。
- 未提供目标点文件且未选择节点集时，提示用户选择目标点文件或节点集。
- 只输出界面当前勾选的节点场；输出路径不得覆盖源 NPZ 或其配套 metadata。

## 数据契约

- 多个节点集取并集并去重，输出节点保持源缓存中的顺序。
- 原样复制 `frequencies`，按所选节点切片 `node_labels`、`node_coordinates` 和所选场的 `<field>_real` / `<field>_imag`。
- 不插值、不重算场值；场数组继续使用 `frame,node,component` 布局。
- 输出 metadata 更新节点列表、字段点列表、数组形状、来源文件和筛选条件。
- 输出只保留所选节点集，并将其成员索引重映射到新的节点顺序，使输出仍可作为缓存继续使用。

## 实现范围

- 在现有缓存处理模块中增加一个直接切片函数，复用已有 metadata 读取、节点集校验和 NPZ/JSON 保存逻辑。
- 启动器根据是否存在目标点文件，在“插值”和“节点集直接提取”之间分派。
- 不增加运行模块、第三方依赖、CSV 输出或新的插值算法。

## 错误处理

- 缓存缺少配套 metadata、节点集定义、成员索引数组或必要字段数组时停止并报告明确错误。
- 空节点集、越界索引、字段数组与 metadata 形状不一致时停止，不生成部分输出。
- 多个节点集共享节点时只输出一次该节点。

## 验证

- 先添加失败测试，验证单个/多个节点集的并集、节点顺序、原始数值、所选字段和重映射索引。
- 验证 GUI 校验允许“无目标点 + 有节点集”，并正确分派到直接提取函数。
- 运行缓存、插值和启动器相关测试，确认原有目标点流程不变。
